# Chicken-date shared shopping list

One link. One list. No login.

Your cat-comic styling, pantry checklist, shopping stops, inventory and judging-cat popup are retained. Firebase Firestore saves changes and sends them to both phones automatically.

**Follow [SETUP.md](SETUP.md) for the beginner-friendly Firebase and Vercel instructions.** No SQL, email setup or user accounts are needed.

## Run locally

Use Node.js 22+. Copy `.env.example` to `.env.local`, fill in the three Firebase settings, then:

```sh
npm ci
npm run dev
```

Open Vite's localhost URL, not the HTML file directly. To check the project:

```sh
npm test
npm run build
```

## Use with your date

Open the deployed page, load the chicken ingredients, then press **Copy shared link**. Send the complete URL including `?list=…`. Anyone who has that URL can edit the list. Bookmark it on both phones.

Changes are stored in `shoppingLists/{randomListId}` as one small document containing `revision` and `items`. A Firestore `onSnapshot` listener handles live updates. Transactions compare revisions to avoid silently overwriting simultaneous changes. Reset empties the document's items after confirmation and keeps the URL valid. Editing requires a connection; saved data remains on the server.

The supplied rules deny listing the whole collection and direct document deletion, and validate document keys, revision and a 200-item limit. The client validates individual item fields and escapes names/notes before rendering. This is link-based access, not authentication. Anyone with a list ID can change that list through the app or API. The Firebase web configuration is public; the random list ID is the sharing capability.

## Files

- `index.html`, `style.css`: existing design and page wording.
- `src/main.ts`: Firestore connection, sharing and page interactions.
- `src/model.ts`: item validation and atomic list transformations.
- `src/ingredients.ts`: your original ingredients and store assignments.
- `firestore.rules`: copy into Firebase's Rules tab and publish.
- `.env.example`: the three public Firebase settings.
- `vercel.json`: Vite deployment configuration.
- `public/` and `src/sw-template.js`: retained app icons and public app-shell caching. Firestore data is never cached by this service worker.

`dist` is generated by the build. The previous Supabase integration, sign-in UI and database scripts have been removed. Existing data in a previous backend is not automatically copied; use the original ingredient button or add items here.

Live Firebase connection and Vercel deployment are still yours to configure. The local build and tests pass; real-phone sync has not yet been verified.
